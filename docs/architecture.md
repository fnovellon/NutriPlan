# Architecture

Complète `CLAUDE.md`, qui garde les règles nutritionnelles (elles font foi). Une section citée « … » sans fichier est dans `CLAUDE.md` ou dans un autre fichier de `docs/`. À mettre à jour dans le même commit que le code qu'il décrit.

- La page publiée est un seul fichier autonome, `index.html` : CSS + JavaScript vanilla en ligne, aucune dépendance à l'exécution. Polices Google Fonts (Archivo, Newsreader) avec polices de secours.
- Elle est construite à partir de `src/` par `npm run build` (`build.js`, sans dépendance) : **on modifie `src/`, jamais `index.html` à la main**, puis on reconstruit ; `npm test` refuse de tourner si `index.html` n'est pas à jour. Le gabarit `src/page.html` (tête, balisage de tous les écrans) inclut les autres fichiers avec `{{inclure fichier}}` (le fichier sans son dernier saut de ligne, inclusions comprises) et `{{base64 fichier}}` (chemins relatifs à `src/`) :
  - `src/style.css` : toute la feuille de style ;
  - le moteur, sans DOM, dans cet ordre :
    - `src/engine/base.js` : `'use strict'`, `APP_VERSION`, outils communs (`has`, `it`, `mac`, `unitMac`, `scaleOf`, `sc`, `pieces`, `slices`, `meat`, `total`, `typo`…) ;
    - `src/engine/types.js` : types JSDoc des objets du moteur (`Item`, `Section`, `Plan`, `Choices`, `Profile`, `Energy`, `Day`…), commentaires seulement ;
    - les données : `src/data/aliments.js` (`FOOD`, `UNIT`, `STARCH`, `YIELD`, `REF_GROUPS`, `refTable`), `src/data/menus.js` (`DESSERT`, `PD`, `PROT`, `DEFAULT_CHOICES`), `src/data/recettes.js` (`RFOOD`, `VEG_IDS`, `ONION_G`, `onionQty`, `onionName`, `onionNote`, `RECIPES`, `recipesFor`, `recipeOf`, `recipeItems`) ;
    - les calculs, par sujet : `src/engine/seances.js` (tailles, moments, plan d'un jour, semaine type), `profil.js` (profil, dépense, `energy`), `choix.js` (aliments proposés, `withAllowed`, `tieredPick`, `randomChoices`, recettes favorites et à éviter : `cleanRecipeIds`, `recipePref`), `semaine.js` (`weekBalance`, `weekNeeds`), `repas.js` (lignes de chaque repas, `mainItems`), `journee.js` (limites, `splitStarch`, `composeDay`, `buildDay`), `batch.js` (`batchChoices`, `batchCook`), `courses.js` (`shoppingList`) ;
  - l'interface, `src/ui/`, un fichier par écran, tous dans le `if (typeof document !== 'undefined'){ … }` écrit dans le gabarit (déclarations communes à ce bloc ; une `const` doit être déclarée avant d'être lue au chargement, et l'ordre d'inscription des écouteurs est gardé) : `etat.js` (stockage, profil, dates, jour affiché, plats, `writeDay`, `planForMeal`, et la table `ACTIONS`), `page.js` (bulles de choix, lignes, recettes, cartes, frise, séances en pastilles et leur panneau, total, `render`), `ecrans.js` (pile d'écrans, historique, menu : `navTo`, écran surligné), `repas.js` (formulaire des repas), `periodes.js` (champs Du / Au), `planifier.js` (Planifier : planifications, nouvelle planification, tirage de la période), `semaine.js` (« Ta semaine », tirages équilibrés), `courses.js` (planifications enregistrées et leur migration, détail d'une planification : récap, batch cooking, courses ; fiche d'une recette du batch et sa page), `panneau.js` (panneau de choix, fiche de recette `showRecipe`, Échap, retour du téléphone), `recettes.js` (bibliothèque des recettes, 3.24.0), `semtype.js` (éditeur de semaine type, réglages et accueil, 3.18.0), `accueil.js`, `actions.js` (le clic), `reglages.js` (onglets, « Tes besoins », aliments, champs du profil, effacer), `demarrage.js` (retour sur l'onglet, table de l'aide, premier dessin, appli installable) ;
  - boutons : chaque `data-action` est une entrée de `ACTIONS`, ajoutée par son écran (`Object.assign(ACTIONS, {…})`) ; l'action reçoit le bouton et `data-value`, renvoie un message (même vide) pour que la page soit redessinée (message dans `#hint`, alerte des repères de la semaine, focus gardé sur la recette ou le bouton d'une carte), rien si elle a fini ;
  - `src/apple-touch-icon.png` : l'icône de l'écran d'accueil de l'iPhone, mise en ligne en base64.
  Les fichiers JavaScript sont recollés dans un seul `<script>`, dans l'ordre du gabarit : leurs déclarations de premier niveau restent communes, et une constante lue au chargement d'un fichier doit être déclarée dans un fichier précédent. Une ligne `{{# …}}` du gabarit est un commentaire, retiré de la page.
- Appli installable (PWA, 3.5.0), seuls fichiers à côté de `index.html` (un service worker est forcément un fichier à part ; ouverte seule depuis un fichier, la page marche comme avant) :
  - `manifest.webmanifest` : « Repas du jour », nom court « Repas », `display: standalone`, adresses relatives (`./`, le site est dans un sous-dossier de GitHub Pages), couleurs papier, icônes ;
  - `icons/` : `icon-192.png`, `icon-512.png` (l'icône de la page) et `icon-maskable-512.png` (fond plein, dessin réduit à 80 % pour la zone sûre d'Android), dessinées depuis le SVG de l'icône ;
  - `sw.js` : service worker. Page : réseau d'abord (nouvelle version dès qu'on est connecté), copie gardée hors connexion (repli sur `./` puis `./index.html`). Manifeste, icônes et polices Google : copie d'abord. Autres sites et requêtes autres que GET : pas touchés. Cache `repas-du-jour-v1`, à changer seulement si la liste `CORE` change ; les anciens caches sont effacés à l'activation ;
  - dans `index.html` : lien vers le manifeste, métas de l'écran d'accueil de l'iPhone (`apple-mobile-web-app-*`, barre d'état `default`), `apple-touch-icon` déjà en PNG ; service worker enregistré seulement si `serviceWorker` existe et que la page est servie en http(s) ; `beforeinstallprompt` gardé pour le bouton « Installer l'appli » des réglages (`#install`, caché sinon, caché aussi après `appinstalled`).
  - Sur iPhone, l'appli installée a son propre stockage, séparé de Safari (l'accueil est à refaire une fois) ; sur Android, le stockage est partagé avec Chrome.
- Le moteur (données + `buildDay`) est pur et testable hors navigateur. L'initialisation du DOM est protégée par `if (typeof document !== 'undefined')` : garder cette séparation.
- Données :
  - `FOOD` : valeurs pour 100 g `[kcal, protéines, glucides, lipides]` ; `UNIT` : valeurs par pièce (banane ≈ 120 g de pulpe, pomme ≈ 150 g, compote 100 g, œuf moyen ≈ 50 g). Source : table Ciqual de l'Anses, arrondie, glucides disponibles (sans les fibres), vérifiée aliment par aliment en 3.3.1 ; skyr et halloumi d'après les étiquettes, légumes = moyenne de légumes verts. Toute nouvelle valeur doit venir de Ciqual (ou de l'étiquette pour un produit de marque). Ajoutés en 3.12.0 pour les recettes, d'après Ciqual (relue sur les sites qui la reprennent, arrondie) : 17 légumes crus (oignon, tomate, pulpe de tomate, poivron, courgette, champignon, épinards, brocoli, carotte, petits pois cuits, haricots verts, concombre, aubergine, chou-fleur, chou, poireau, salade) et les matières grasses (lait de coco, crème légère 15 à 20 %, lait demi-écrémé, graines de sésame, olives noires en saumure ; tahini d'après l'étiquette). Énergie des légumes = Ciqual, fibres comprises (2 kcal/g) : l'écart avec 4/4/9 peut atteindre 10 kcal pour 100 g.
  - Groupes (3.7.0) : un choix peut regrouper des aliments aux valeurs proches, avec les valeurs du premier, seulement si l'énergie est à ≈ 10 % près et protéines et lipides à ≈ 3 g près pour 100 g (sinon, un choix à part). Flocons d'avoine ou muesli sans sucre ajouté (`avoine` : muesli floconneux aux fruits secs, sans sucre ajouté, 378 kcal, 11,3 g, 61,8 g, 7,6 g ; 3.8.0) ; viande blanche maigre (`poulet` : poulet, dinde, filet mignon de porc ≈ 125 kcal, 23 g, 4 g) ; poisson gras (`saumon` : saumon, maquereau, sardines à l'huile égouttées ≈ 222 kcal, 26 g, 13 g) ; lentilles ou haricots rouges (secs 314 kcal, 22,5 g, 1 g) ; fruits secs (`fruitsSecs` : moyenne d'abricots, pruneaux et figues, 245 kcal). Libellé du choix et détail (`sub`) : « Flocons d'avoine » / « ou muesli sans sucre ajouté », « Viande blanche » / « poulet, dinde, filet mignon de porc », « Poisson gras » / « saumon, maquereau, sardines à l'huile », « Fruits secs » / « abricots, pruneaux, figues ». Les identifiants (`poulet`, `saumon`) n'ont pas changé : rien à migrer.
  - Ajoutés en 3.7.0 : tofu ferme nature (148 kcal, 14,4 g, 1,1 g, 9,3 g), pois chiches secs (351 kcal, 20,5 g, 47,5 g, 5,9 g), fruits secs.
  - `STARCH` : féculents (poids cru, pas d'arrondi, plafond `cap` en grammes crus pour 72 kg, cuissons `cook : [[facteur, accord], …]`, accord du cru `raw`) ; `STARCH_ORDER` pour l'ordre des boutons ; `starchCap(id, k)` donne le plafond en kcal.
  - Chaque aliment (`it()`) porte ses macros `m` et, si c'est pertinent, `cook : { raw, ways : [{ g, adj }, …] }`, le poids cuit estimé pour chaque cuisson. Viande et poisson : rendements `YIELD` (poids cuit / cru, ≈ table USDA des rendements de cuisson 2012) : poulet 0,75, bœuf haché 0,75, poisson blanc 0,80, saumon 0,80, arrondi à 5 g. Féculents : facteurs de `STARCH` (riz 3, pâtes 2,3, quinoa 2,7, semoule 2,3, boulgour 2,5, lentilles 2,5, pois chiches 2,2), arrondi à 10 g. Pommes de terre et patate douce : deux cuissons, à l'eau × 1 (le poids bouge à peine) et au four × 0,75 (≈ 25 % d'eau perdue en morceaux rôtis). Pas de poids cuit pour les gnocchis, le tofu ni pour les aliments déjà prêts (crevettes cuites, jambon, thon, œufs, halloumi).
  - `PROT` : 8 protéines (viande blanche, bœuf 5 %, poisson blanc, poisson gras, crevettes + halloumi, œufs + jambon, thon, tofu ferme : 200 g × k × `pf`, sans ajout gras), chacune avec ses ajouts gras au déjeuner (`dej`) et au dîner (`diner`) : 25 g d'amandes fixes au dîner avec viande blanche et poisson blanc (`amandesDiner()`, clé `dam`, « sur les légumes ou en fin de repas » ; à la place du ½ avocat depuis la 3.10.0 : plus d'avocat dans l'appli), parmesan avec le bœuf. Plus d'huile dans les recettes depuis la 3.1.0 : la marge cuisine couvre la matière grasse de cuisson. `PROT_ORDER`. Remplacement proposé en note, de même énergie arrondie à 5 g (`swapGrams`) et fixe comme ce qu'il remplace : « ou 20 g de parmesan » pour l'œuf dur du thon.
  - `RECIPES` (3.12.0, remplace `IDEAS`) : une recette par couple protéine × féculent (8 × 10), identifiant `prot-starch` (`poulet-riz`) : titre `t`, minutes `min`, `box` (se garde, à emporter), légumes `leg` (`{ id: g }`, 250 g en tout ; oignon : 50 ou 100 g depuis la 3.27.0), matière grasse `cuis` (`[aliment, g, nom, mesure]` : `H1` 5 g d'huile « 1 c. à café », `H2` 10 g « 2 c. à café », huile de sésame, 15 g de lait de coco ou de crème légère « 1 c. à soupe », 5 g de parmesan râpé, 3 g de graines de sésame, 15 g d'olives, 5 g de tahini, 50 g de lait), aromates `aro` (ne comptent pas), ajouts `plus` (`skyr` ou `miel` en grammes, « pour la sauce »), trois étapes `steps`, note `soir` des amandes ou du parmesan du dîner, `gel` (se congèle bien, 3.13.0 : pas les salades, taboulés et bowls aux crudités, c'est-à-dire sans salade ni concombre et dont le titre ne commence pas par Salade, Taboulé, Bowl ou Poke). Textes passés par `typo()` (espaces insécables). `RFOOD` : nom et précision de chaque légume ou matière grasse (ligne du repas et courses) ; `VEG_IDS` : les légumes. `recipesFor(prot, starch)` : les recettes d'un couple (une pour l'instant) ; `recipeOf(choix)` : la recette choisie (`choix.recette`) si elle existe (`has`) et va avec sa protéine et son féculent, sinon `null` ; `recipeItems(id)` : ses lignes, clés `v-<légume>`, `f-<aliment>`, `x-skyr` / `x-miel`. Oignon en unités (3.27.0, `ONION_G` = 100 g, un oignon moyen épluché) : `onionQty(g)` « ½ », « 1 », « 1 ½ » (au demi le plus proche), `onionName(g)` « oignon » ou « oignons » (à partir de 2), `onionNote(g)` « ≈ 50 g, ou 2 échalotes » (le poids seul au-delà d'un oignon) ; la ligne garde `buy` en grammes ; `batchCook` les reprend pour ce qu'il faut cuire, `shoppingList` arrondit à l'oignon entier au-dessus (« 3 oignons », « pour ≈ 250 g, ou des échalotes »).
  - `PD` (3.8.0) : bases du petit-déjeuner (`avoine`, `pain`, `sale` : libellé et `sub` éventuel, « Salé » / « pain complet, œufs, jambon ») et `PD_ORDER` ; identifiants validés avec `has(PD, …)`.
  - `DESSERT` (`aucun`, `fruit`, `compote`, `fruitsSecs`, `chocolat` : libellé, `sub` éventuel et `item()`, clé `des`) et `DESSERT_ORDER` ; `dessertOf(choix)` renvoie `'aucun'` si le dessert est absent ou invalide.
  - Aliments proposés (3.7.0) : `CHOICE_IDS` (`pd`, `prot`, `starch`, `dessert` sans `aucun`), liste des aliments qu'on peut retirer des propositions ; profil `off` = `['prot:thon', …]`. `cleanOff(o)` valide (identifiants connus, sans doublon, 100 au plus) et oublie tout un type entièrement retiré (il reste toujours une base, une protéine et un féculent ; les desserts peuvent tous l'être, « Aucun » reste). `allowed(kind, off)` : les identifiants proposés, dans l'ordre (`aucun` toujours en tête des desserts). `withAllowed(c, off)` : pour la mémoire du jour de la semaine et les choix par défaut, un aliment retiré est remplacé par le suivant proposé dans l'ordre (en boucle), un dessert retiré par `aucun`, et une protéine remplacée jamais par celle de l'autre repas (s'il en reste au moins deux). `randomChoices(rand, off)` ne tire que des aliments proposés.
  - `REF_GROUPS` et `refTable()` : table de référence des aliments pour l'écran d'aide, groupes (protéines, féculents crus, petit-déjeuner et douceurs, légumes crus, matières grasses et sauces, à la pièce) avec libellés ; les valeurs viennent de `FOOD`, `UNIT` et `STARCH`. Tout aliment ajouté doit y figurer (vérifié par les tests).
  - `SIZES` (petite, moyenne, longue : titre du bandeau et coût net par kg), `MOMENTS`, `MAX_SEANCES` (4), `DUREES` (longue).
  - Plan d'un jour : `{ seances: [{ taille, moment, duree? }], libre }`. `cleanSeances(l)` (au plus 4, une seule longue, toujours le matin). Semaine type (3.11.0) : `cleanWeek(o)` → `{ jours: { getDay: [séances] }, libre: getDay }` (jours sans séance omis, repas libre le samedi par défaut). `emptyPlan(js, sem)` : un jour pas encore rempli, séances de la semaine type (aucune sans elle) et repas libre son jour (samedi sans elle) ; `cleanPlan(p, js, sem)` : ce qui est enregistré (`seances`, `libre`) l'emporte, champ par champ, le reste vient de `emptyPlan` ; `migratePlan(p)` (plan d'avant la 2.0.0 → séances).
  - `DEFAULT_CHOICES` : choix de repas par défaut par jour, indexés par `Date.getDay()` (0 = dimanche). `randomChoices(rand, off, bal, k)` : « Décide pour moi », chaque choix tiré au hasard parmi les aliments proposés (`rand` dans [0, 1[, `Math.random` par défaut), dans l'ordre base, déjeuner, dîner ; jamais la même protéine au déjeuner et au dîner (s'il en reste au moins deux), jamais « Œufs + jambon » avec le petit-déjeuner salé (s'il reste autre chose) ; la recette du couple protéine × féculent est choisie d'office (`recette`, sans tirage tant qu'il n'y en a qu'une). Avec `bal` (repères du reste de la semaine, voir « Équilibre de la semaine ») et `k`, tirage pondéré : poisson × 3 tant qu'il en manque (saumon × 6 s'il manque aussi le poisson gras), lentilles et pois chiches × 3 tant qu'il manque des légumes secs ; bœuf (≈ 150 g × k crus × 0,75 cuits), « Œufs + jambon » (90 g × k de jambon) et salé (45 g × k) écartés s'ils feraient dépasser la viande rouge ou la charcuterie ; chaque repas tiré compte pour le suivant ; si tout ce qui reste dépasse, le tirage se fait parmi eux, en écartant d'abord « Œufs + jambon » avec le salé (« jamais la même protéine » passe avant, puis pas d'œufs-jambon avec le salé, puis les repères). Sans `bal` : tirage uniforme (aux bornes, premier et dernier choix proposés).
  - Recettes favorites et à éviter (3.25.0) : `cleanRecipeIds(o)` (identifiants de `RECIPES`, sans doublon), `recipePref(id, prefs)` (0 à éviter, 2 favorite, 1 sinon ; `prefs` = `{ fav, ban }`, le profil). `randomChoices(rand, off, bal, k, prefs)` : avec `prefs` (seulement quand les plats sont des recettes), le féculent pèse le poids de la recette du couple, la protéine la part pondérée de ses couples ; sans préférence, exactement le même tirage. `batchChoices(…, rand, prefs)`, `batchSwapOptions(…, k, prefs)`, `batchSwapPick(…, rand, prefs)` : recettes à éviter écartées, favorites × 2. La suggestion d'un repas (`buildDay`, `suggest`) n'est jamais une recette à éviter.
  - `tieredPick(rand, liste, poids)` : tirage pondéré partagé (poids > 0 tirés au prorata ; 0 écartés ; < 0 écartés d'abord ; sans poids positif, tirage parmi les poids nuls, sinon parmi tous), utilisé par `randomChoices` et `batchChoices`.
  - Batch cooking (3.13.0, voir la section) : `BATCH_N` (3, 4, 5), `BATCH_BLOCK` (7 jours), `FRIDGE_DAYS` (3), `batchChoices(jours, n, off, k, rand)` (plats d'une période), `batchCook(jours, lead)` (fiche de cuisine) ; changer une recette (3.16.0) : `batchSwapOptions(jours, id, off, k)` (recettes possibles, `jours` = `[{ ch, libre }]` d'un bloc), `batchSwap(jours, id, nid, off)` (plats avec la nouvelle), `batchSwapPick(jours, id, off, k, rand)` (« Une autre au hasard »), `batchMeals(jours)` (repas servis) ; chiffres ronds et jambon par paquet (3.17.0) : `batchRound(jours, profil)` (`jours` = `[{ plan, ch }]`), `HAM_SLICES` (4), et dans `src/engine/repas.js` `BATCH_GRAMS` (pas des portions qui se pèsent, `[p1, p2]`) et `fixedGrams(choix)` (poids fixés valides d'un repas, `[p1, p2]` ou `null`) ; `PROT[p].base(k, g)` prend ces poids.
  - `PROFILE_DEFAULT`, `PROFILE_RANGES`, `NEAT` : profil par défaut, bornes des champs, activité hors sport.
- `seanceCost(séance, profil)`, `dayCost(plan, profil)`. `energy(plan, profil)` renvoie `{ bmr, rest, restSource, cost, need, deficit, target, kgWeek }` (`mode` : `'auto'` ou `'manuel'` ; `restSource` : `'calcul'` ou `'saisie'`).
- `splitStarch(budget, part, k, off, caps)` : `off = { dej, diner }`, kcal des desserts, prises sur le féculent du même repas ; `caps = { dej, diner }`, plafonds en kcal de chaque repas.
- Chaque ligne (`it(key, qty, name, note, m, cook, buy)`) porte `buy`, ce qu'il faut acheter : `{ id, g }` en grammes crus, `{ id, n }` en pièces (boîte de thon, fruit du dessert `fruit`, doses de `shaker`, `libre`) ou `{ id, kcal }` pour un budget (`encas`, `marge`) ; `mac()` et `unitMac()` le remplissent, `ravito` est en grammes de glucides. `shoppingList(days)` additionne les achats de plusieurs résultats de `buildDay` et les range par rayon (`SHOP_AISLES` : viandes et poissons, crèmerie, œufs et tofu, pain et féculents crus, fruits et légumes, épicerie, le reste) : poids (`shopQty`, en kg au-delà de 1 000 g), pièces accordées, œufs, tranches de pain et de jambon, huile de la marge cuisine (kcal / 9) ; légumes des recettes aux fruits et légumes (pulpe de tomate à l'épicerie), crème et lait à la crèmerie, lait de coco, olives, sésame et tahini à l'épicerie, huile (recettes et huile de secours) sous « huile d'olive », noms et précisions de `RFOOD`. Toute nouvelle ligne d'aliment doit avoir son `buy` et son rayon (vérifié par les tests).
- `composeDay(plan, choices, profil, pf)` construit la journée pour un facteur de protéines `pf` donné ; `buildDay(plan, choices, profil)` cherche `pf` (voir « Objectif de protéines ») et renvoie `{ secs, tot, libre, imprevu, energy, ecart, scale, prot }` : `secs` est la journée dans l'ordre (repas + bandeaux de séance, ceux-ci avec le moment et le coût de leur séance, `moment`, `kcal`, 3.20.0 : la frise et les cartes de la page), `tot` les totaux, `libre` le budget du repas libre, `ecart` l'apport moins l'objectif (hors repas libre), `scale` le facteur de portions `k`, `prot` `{ target, low, high, floor, factor }` (fourchette ± 10 %, `floor` = `low`), `imprevu` (3.26.0) `{ slot, kcal, mode, delta, over }` ou `null` (`delta` : l'écart avec le repas prévu, `over` : ce qui n'a pas pu être repris, la journée en plus ou en moins ; la section du repas a `imprevu`, et, à la place, ni `pick` ni `recipe` ni `suggest`). Le plan peut avoir `imprevu` (`cleanImprevu`, `IMPREVU_SLOTS`, `IMPREVU_KCAL` dans `seances.js`) : `pf` est cherché sans lui, comme sans repas libre. Le profil est facultatif (valeurs par défaut).
- Portions : `scaleOf(profil)` donne `k`, passé explicitement aux constructeurs de repas (`breakfast`, `snackItems`, `gouterItems`, `mainItems` → `PROT[p].base(k × pf)` / `.dej(k)` / `.diner(k)`, `amandesDiner()` fixe) ; les portions ajustées à l'objectif de protéines reçoivent `k × pf` et sont marquées `adj` (`adj(item)`) ; `PROT.thon.fixe` (la boîte ne s'ajuste pas) ; `sc(g, pas, k)` arrondit au pas, `pieces(n, k)` à l'unité, `slices(g, par)` écrit « 2 tranches » ou « environ 3 tranches ».
